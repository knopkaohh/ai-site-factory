# AI Site Factory

Платформа для автоматизированного редизайна сайтов. Пользователь создаёт проект по домену существующего сайта и краткому техническому заданию. Дальше платформа должна собирать исходный сайт, готовить паспорт, концепцию, новый сайт, проверять его и собирать демоверсию.

В этом репозитории реализован первый спринт: рабочая панель, хранение проектов в SQLite и API управления проектами. Сбор сайта, анализ, генерация, тестирование и публикация ещё не выполняются и не имитируются.

## Структура репозитория

```
backend/            HTTP API, SQLite и границы будущих сервисов
frontend/           рабочая панель на React
shared/src/         общие типы, статусы, нормализация домена и валидация
docs/ARCHITECTURE.md
backend/data/       файл базы данных (создаётся при запуске, в git не входит)
```

Frontend и backend живут в одном репозитории и связаны npm workspaces. Отдельной инфраструктуры, Docker и платных сервисов нет.

## Требования к окружению

- Node.js 22.13 или новее
- npm 10

База данных — встроенный модуль `node:sqlite`. Отдельный сервер SQLite устанавливать не нужно. На Node.js 22 модуль может вывести предупреждение ExperimentalWarning: это ограничение платформы Node, а не отказ базы.

## Установка

```bash
npm install
```

## Запуск

В двух процессах, с проксированием `/api` через Vite:

```bash
npm run dev
```

- Панель: http://127.0.0.1:5173
- API: http://127.0.0.1:3001

По отдельности: `npm run dev:backend` и `npm run dev:frontend`.

Production-сборка и запуск одной командой API, которая отдаёт и собранную панель:

```bash
npm run build
npm start
```

Панель и API после `npm start` доступны на http://127.0.0.1:3001.

Переменные окружения:

- `PORT` — порт API, по умолчанию `3001`
- `DATABASE_PATH` — путь к файлу SQLite относительно корня репозитория. По умолчанию `backend/data/app.db`

Файл `.env` автоматически не читается.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run check
```

`npm run check` последовательно запускает проверку типов, тесты и production-сборку.

## База данных

Проекты хранятся только в SQLite на стороне backend. Браузерный `localStorage` для проектов не используется. Демонстрационные проекты в базу не добавляются.

При первом запуске создаются таблицы `projects`, `project_stages`, `project_events` и `schema_migrations`. Для проекта сразу создаются семь этапов со статусом «Ожидает» и событие о создании. Внешние ключи включены: удаление проекта удаляет его этапы и историю. Даты хранятся в ISO 8601 UTC.

Каталог `backend/data/` сохраняется между перезапусками процесса. Удаление файла `app.db` очищает данные.

## Реализовано

- Список проектов, поиск по названию и домену, фильтр по статусу.
- Счётчики всех проектов, проектов в работе и готовых демоверсий.
- Создание проекта с валидацией на клиенте и на сервере.
- Нормализация домена без загрузки исходного сайта.
- Страница проекта: параметры, этапы, прогресс и история.
- Изменение названия, домена, ТЗ, особых требований и режима работы.
- Удаление проекта после подтверждения в интерфейсе.
- Страница настроек: версия, состояние backend и базы, честные статусы ещё не подключённых интеграций.
- `GET /api/health`, `GET/POST /api/projects`, `GET/PATCH/DELETE /api/projects/:id`.

## Пока не реализовано

- Краулер, анализ и паспорт сайта.
- Концепция, дизайн-система и генерация кода.
- Автоматическое тестирование и исправление.
- Подготовка демоверсии и публикация.
- ИИ-модели и внешние API.
- Очередь фоновых задач и запуск этапов из интерфейса.

Статусы этапов не переводятся в «Завершён» искусственно. Пока сервисы не подключены, новый проект остаётся в статусе «Создан», а этапы — «Ожидает».

## Дальнейшая автоматизация

Границы модулей `crawler`, `analyzer`, `designer`, `developer`, `qa` и `publisher` описаны в `backend/src/automation/` и в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Подключение сервиса не должно блокировать HTTP-запрос: этап переводится в работу транзакцией, сама операция выполняется после ответа клиенту.
