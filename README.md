# AI Site Factory

Платформа для автоматизированного редизайна сайтов. Пользователь создаёт проект по домену существующего сайта и краткому техническому заданию. Дальше платформа должна собирать исходный сайт, готовить паспорт, концепцию, новый сайт, проверять его и собирать демоверсию.

В этом репозитории работают панель проектов и сбор исходного сайта по сохранённому адресу. Анализ, генерация, тестирование и публикация ещё не выполняются и не имитируются.

## Структура репозитория

```
backend/            HTTP API, SQLite и сбор исходного сайта
frontend/           рабочая панель на React
shared/src/         общие типы, статусы, нормализация адреса и валидация
docs/ARCHITECTURE.md
backend/data/       база SQLite и файлы сбора (создаются при запуске, в git не входят)
```

Frontend и backend живут в одном репозитории и связаны npm workspaces. Отдельной инфраструктуры, Docker и платных сервисов нет.

## Требования к окружению

- Node.js 22.13 или новее
- npm 10

База данных — встроенный модуль `node:sqlite`. Отдельный сервер SQLite устанавливать не нужно. На Node.js 22 модуль может вывести предупреждение ExperimentalWarning: это ограничение платформы Node, а не отказ базы.

## Установка

```bash
npm install
```

## Запуск

В двух процессах, с проксированием `/api` через Vite:

```bash
npm run dev
```

- Панель: http://127.0.0.1:5173
- API: http://127.0.0.1:3001

По отдельности: `npm run dev:backend` и `npm run dev:frontend`.

Production-сборка и запуск одной командой API, которая отдаёт и собранную панель:

```bash
npm run build
npm start
```

Панель и API после `npm start` доступны на http://127.0.0.1:3001.

Переменные окружения:

- `PORT` — порт API, по умолчанию `3001`
- `DATABASE_PATH` — путь к файлу SQLite относительно корня репозитория. По умолчанию `backend/data/app.db`

Файл `.env` автоматически не читается.

## Проверки

```bash
npm run typecheck
npm test
npm run build
npm run check
```

`npm run check` последовательно запускает проверку типов, тесты и production-сборку.

## База данных

Проекты хранятся только в SQLite на стороне backend. Браузерный `localStorage` для проектов не используется. Демонстрационные проекты в базу не добавляются.

При первом запуске создаются таблицы проектов, этапов, истории и сбора. Для проекта сразу создаются семь этапов со статусом «Ожидает» и событие о создании. Внешние ключи включены: удаление проекта удаляет его этапы, историю и записи сбора. Даты хранятся в ISO 8601 UTC.

HTML страниц и скачанные изображения лежат в `backend/data/crawls/<проект>/<запуск>/`, а не в SQLite. Каталог `backend/data/` сохраняется между перезапусками процесса. Удаление `app.db` очищает записи; файлы сбора удаляются вместе с проектом.

## Реализовано

- Список проектов, поиск по названию и домену, фильтр по статусу.
- Счётчики всех проектов, проектов в работе и готовых демоверсий.
- Создание проекта с валидацией на клиенте и на сервере.
- Нормализация домена и сохранение стартового URL. Создание проекта сайт не загружает.
- Страница проекта: параметры, этапы, прогресс, история и сбор исходного сайта.
- Изменение названия, домена, ТЗ, особых требований и режима работы.
- Удаление проекта после подтверждения в интерфейсе.
- Страница настроек: версия, состояние backend и базы, лимит страниц сбора, честные статусы интеграций.
- Сбор исходного сайта в фоне: страницы того же домена, sitemap, robots.txt, текст, ссылки и изображения.
- `GET /api/health`, `GET/POST /api/projects`, `GET/PATCH/DELETE /api/projects/:id`.
- `POST /api/projects/:id/crawls`, просмотр запуска, страниц, сводки и отмена.
- `GET/PATCH /api/settings/crawl` — лимит страниц от 1 до 200.

## Пока не реализовано

- Анализ и паспорт сайта.
- Концепция, дизайн-система и генерация кода.
- Автоматическое тестирование и исправление.
- Подготовка демоверсии и публикация.
- ИИ-модели и внешние API.

Этап сбора становится «Завершён» только если запуск обошёл найденные страницы без ошибок и без обрезки по лимиту. Частичный результат остаётся в истории и не считается полным завершением. Следующие этапы сами не запускаются.

## Дальнейшая автоматизация

Сбор реализован в `backend/src/crawl/`. Остальные модули описаны в `backend/src/automation/` и в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Запуск сбора отвечает сразу, страницы загружаются после ответа клиенту.
